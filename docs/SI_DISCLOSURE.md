# Super Intelligence (SI) disclosure

## Submission answer

Yes. We used Codex and Claude as SI development assistants while preparing Guardian
(formerly AstroVitals / Mission Baseline). They assisted with project implementation and
documentation; Codex also helped add SI acknowledgments and provenance metadata.
The solution includes an optional Qwen3-8B language-model integration through Ollama for
explanations, with decisions controlled by an onboard rule engine, plus machine-learning
pipelines for heart and jugular-vein ultrasound segmentation and derived measurements.
Synthetic training and demonstration scenarios are identified separately from cited public
datasets and uploaded measurements. SI use is acknowledged in the project README, the
app's Citations page, and machine-readable provenance metadata. Model-generated ultrasound
overlays carry a visible SI label and embedded PNG metadata.

## Code and data scope

- **Development tools:** Codex and Claude, confirmed by the project owner. Exact model
  versions and a complete per-file contribution history were not supplied. This is a
  project-level acknowledgment, not a claim that every file was generated by SI.
- **This disclosure change:** Codex generated the disclosure text, metadata, app notices,
  and code to label model-generated ultrasound overlays.
- **Language model:** `ai/Modelfile`, `ai/train_unsloth.py`, and
  `apps/server/src/routes/ai.ts` configure Qwen3-8B and optional fine-tuning. The presence of
  a training script does not establish that a fine-tuned model is deployed. API responses
  identify Qwen explanations or the deterministic fallback through their `source` field.
- **Ultrasound models:** `ai/heart_ultrasound/` and `ai/jugular_ultrasound/` contain model
  pipelines and results. Predicted masks, derived measurements, and evaluation predictions
  are machine-learning outputs. They are not original clinical observations. The service
  labels its output images and includes provenance metadata in its JSON results.
- **Synthetic examples:** `astrovitals_ai_triage_code`, `ai/daily_crew_telemetry.json`, and
  `apps/server/src/wearables/providers/demo.ts` provide training or demonstration scenarios.
  Synthetic does not automatically mean generated by a language model; these include
  programmed examples and simulation. The exact SI authorship of older data is unverified.
- **Source data:** NASA OSD-575, NASA LSDA, NASA/NOAA API responses, CAMUS, and SegThy
  retain their source attribution. These datasets and original ultrasound frames are not
  relabeled as SI-generated. Existing source licenses continue to apply.

Machine-readable scope metadata is stored in
[`apps/web/public/si-provenance.json`](../apps/web/public/si-provenance.json) and served at
`/si-provenance.json`. The telemetry JSON has an adjacent metadata sidecar to preserve its
existing array format.

## Images, videos, audio, and branding

Model-generated ultrasound overlays have a visible `SI-generated overlay` watermark
(`SI` on very small images) and PNG description metadata. The label applies to the
prediction overlay, not to the underlying uploaded scan.

The environment photos have source credits in `apps/web/public/home/README.md`; the 3D
models have credits in `apps/web/public/models/README.md`. Those credits must be retained.
The provenance of decorative mountain imagery and Guardian logo assets has not been
confirmed. No claim is made here that all existing media has been audited or watermarked.

The supplied challenge requirement prohibits NASA branding or design elements in
SI-generated content. Review generated media against that requirement and the
[NASA brand guidelines](https://www.nasa.gov/nasa-brand-center/brand-guidelines/).
This disclosure does not certify the existing visual assets for compliance.
